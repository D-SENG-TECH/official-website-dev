## 08:10 — logo「鋸齒」檢查

- **檢查結果**：
  - 新 SVG 的路徑放大 8 倍仍然平滑。
  - CSS 沒有 `image-rendering`、`transform` 等會讓瀏覽器降低解析度的屬性。
  - 在 1x 與 2x 解析度下截圖，瀏覽器都有正常做反鋸齒。
- **研判原因**：logo 高 46px 時寬度是 201.78px 的小數像素。在 1x 或 1.25x 這類非整數縮放的螢幕上，邊緣會落在半個像素上。
- **決策**：
  - header logo 寬度固定為 202px，footer 為 176px，讓寬度落在整數像素。原本的 `preserveAspectRatio` 會自動置中，不會變形。
  - SVG 根元素加上 `shape-rendering="geometricPrecision"`。
- **替代方案**：
  - 加大 logo 尺寸：會改變設計，沒有採用。
  - 輸出成 PNG：失去向量的優勢，沒有採用。
- **結論**：S 形標誌中間的白色縫隙在 46px 高時只剩約 2px，1x 螢幕本來就難免有些顆粒感。若仍不滿意，可以考慮做一個小尺寸專用、縫隙加寬的版本。

## 14:10 — 首頁 hero 改成即時 3D 產品輪播

- **決策**：首頁 hero 從靜態照片改成 Three.js 即時 3D 輪播，五段場景（AI 監測、空壓機、焊接手臂、風管墊片、奈米超晶體）各約 10 秒、循環播放。每段場景是獨立模組，遵守同一個介面（`create(ctx)` → `{root, duration, update, enter}`），燈光、相機、renderer 由框架統一管，字卡用 HTML 疊在畫面上，四種語言共用同一份 3D。
- **why**：比預錄影片小很多（多數場景用程式建模，只有風機用現成 GLB），而且可以跟著版面縮放、不必替每種語言各輸出一份影片。場景介面先定下來，五段才能分給不同人平行做、最後一次接起來。
- **素材**：AI 監測場景沿用既有的離心風機組裝／爆炸模型（組裝版與爆炸版節點一一對應，可以逐節點補間做出拆解動畫），檔名改成中性名稱，畫面不放任何品牌、客戶或型號。空壓機不用原廠的剖面圖（有版權），螺桿轉子照公開的結構原理自己建模。焊接手臂先用程式做暫代版，保留換成外部產出 GLB 的介面（節點命名 `J1_base`…`J6_flange`、`torch`）。
- **替代方案**：(1) 預錄 MP4/WebM 影片——畫質穩定，但五段加起來檔案大、改一個字卡就要重新輸出；(2) Lottie 2D 動畫——檔案輕，但做不出爆炸圖和氣流的立體感。
- **降級**：使用者開了「減少動態效果」時停在靜態畫格、不自動輪播；hero 捲出畫面或分頁隱藏時暫停渲染。

## 14:25 — hero 改成 Blender Cycles 離線渲染影片

- **決策**：業主要求質感媲美 UE5（含運鏡與打光）。瀏覽器即時渲染即使加上後製也到不了這個水準，手機更吃力，所以改成用 Blender Cycles 光線追蹤離線渲染，每段 10 秒、可無縫循環，輸出影片放進 hero；字卡仍用 HTML 疊在影片上，四種語言共用同一支影片。
- **why**：路徑追蹤才能得到真實的反射、柔和陰影與間接光；影片在任何裝置上的畫質都一樣，播放成本也最低。
- **做法**：所有場景共用同一個 `common.py`，統一 HDRI 攝影棚環境光、四燈佈光（主燈、冷色輪廓光、頂光、暖色補光）、AgX 色調、景深、動態模糊、光暈與暗角後製，以及電影感的相機路徑工具，讓五段看起來像同一支片。每段場景只負責建模、材質與動畫。HDRI 用 Poly Haven（CC0）。
- **替代方案**：(1) 繼續用 Three.js 並加上後製（bloom、SSAO、景深）——可以互動，但質感上限明顯，達不到業主要求；(2) 用 UE5 本身——要另外學一套工具、裝 Windows／大型專案，交付週期太長。代價是失去拖曳旋轉的互動，但業主沒有要求互動。
- **空壓機**：業主確認是兩級壓縮，場景改成兩組螺桿主機，加上中間冷卻器與後冷卻器，氣流顏色依「進氣→第一級升溫→中冷→第二級升溫→後冷」變化。

## 14:55 — 改回網頁即時渲染，Blender 改當資產來源

- **決策**：業主看過後要求 hero 在網頁上即時運轉、之後可能加互動，所以不採用離線影片。改成「Blender 做建模與材質 → 匯出 GLB（Draco 壓縮）→ Three.js 即時播放」：Blender 版場景保留作為資產來源與質感基準，動畫與運鏡移植到 JS。
- **why**：Blender 版已經把造型、材質、比例、運鏡都定案，直接沿用就不必在 JS 裡重新手刻幾何；即時版才能讓訪客拖曳旋轉、之後加熱點說明。
- **框架升級**：共用的 `main.js` 換成與 Blender 版一致的攝影棚設定——同一張 HDRI、AgX 色調、主燈軟陰影、冷色輪廓面光、漸隱地板，後製加上 GTAO（接觸陰影）、bloom、景深、暗角與細微顆粒。手機或 GPU 跟不上時（連續 2 秒每格超過 28 ms）自動降級：關掉 GTAO 和景深、降低解析度。訪客可以拖曳環繞，放手 2.5 秒後回到原本的運鏡；拖曳期間不自動換場。
- **替代方案**：(1) 只把 Three.js 程式模型加上後製——幾何太簡單，質感差距明顯；(2) 用預錄影片加少量互動熱點——業主明確要即時運轉。
- **空壓機轉子**：業主指正第一級陽/陰轉子為上下排列、第二級為左右排列，Blender 資產一併修正。

## 17:20 — 3D 產品動畫改成獨立的 /product-animation 頁、五屏全螢幕捲動

- **決策**：業主要求「動畫放全螢幕，分五個畫面分別放」，完成後放到 `/product-animation/`。做法是一個 sticky 全螢幕 canvas 固定在頁首下方，五個滿版段落疊在上面捲動，用 IntersectionObserver 判斷哪一段在畫面中央就播哪個場景；每個場景自己循環（`auto: false`），不再自動輪播。文字段落沿用首頁「智慧驅動・創新未來」標語，四種語言放在 `product_animation`，「了解更多」連到對應的事業項目頁。執行檔與模型放 `src/assets/product-animation/`（約 3 MB），three.js 用 jsdelivr 的固定版本。首頁 hero 先不動。
- **why**：五段各自完整講一件事，比 10 秒一換的輪播更容易看懂；獨立頁面可以先在 dev 給業主驗收，不影響首頁。
- **質感調整**：色調從 AgX 改成 Neutral（AgX 會把品牌藍洗成灰），拿掉 GTAO（地板在低角度會被壓成一片黑），金屬材質不開 anisotropy（在面光源與沒有切線的 GLB 上會算出 NaN，經 bloom 擴散成整片過曝）。桌機把主體往右移、手機往上移（`setViewOffset`），避免被文字蓋住。
- **素材依據**：每個場景都改成照業主提供的實物資料建模，不自行發揮——風機用聯軸器直結機型，三顆三軸振動感測器照先前核可的位置貼在兩個軸承座與馬達側面、三顆等高；空壓機照實拍照片做開放式機組；墊片照實物照片做外緣包覆唇邊、內圈雙凸筋與長孔；奈米超晶體以配電箱開場；焊接場景加一段圓風管環縫焊接。畫面與檔案中不含任何品牌、型號、廠商或來源名稱，模型節點名也已改成中性名稱，軸承座上的廠牌刻字已從網格中移除。
- **替代方案**：把五段塞回首頁 hero 輪播——首頁首屏負擔太重，而且業主要逐段驗收。

## 19:05 — 首頁 hero 改成滿版 3D 展示間：五個產品同一個場景、按播放依序介紹

- **決策**：業主不要「一段一段切換」的輪播，要五個產品在同一個場景裡：待機時全部入鏡（黑色鏡面地板＋倒影，鏡頭像轉盤一樣約 2 分鐘繞一圈），按「播放產品介紹」後依序播放，前一個產品退到左後方淡出，下一個從它正後方由遠而近滑到前面，鏡頭全程不剪接。首頁標語、副標與「了解事業項目」直接疊在待機畫面上，播放時隱藏，改成每個產品的字卡與五段進度條（可暫停、可點段落跳轉）。
- **why**：同一個空間連續運鏡，比換場更像一支完整的產品片；待機畫面一眼看到全部產品，也保留了原本 hero 的文案與入口。
- **做法**：新增 `showroom.js`，每個產品放在自己的 slot（平移＋等比縮放），各自一份相機與 ctx，場景原本的運鏡在自己的座標系跑、再換算到世界座標，所以五個場景檔幾乎不用改，`/product-animation` 也共用同一份程式與模型。沒有 WebGL 時保留原本的設備照片當背景，文字與按鈕照常可用。
- **替代方案**：(1) 待機用靜止構圖——業主看過後偏好緩慢轉盤；(2) 一般攝影棚地板——保留為 `floor: "studio"` 選項，首頁用鏡面版。

## 20:10 — 首頁 3D 展示間加上四語語音旁白

- **決策**：每個產品一段旁白（加上按播放時的一句開場），四種語言各一組 mp3（48 kbps 單聲道，每語約 300 KB）。旁白完全跟著展示間的狀態走：產品字卡出現時起播、跳段時立刻切掉、暫停／繼續同步、回到待機就停；靜音時仍在背景計時，取消靜音會從正確位置接著講。按下播放才開始下載，而且只抓當前語言的當段與下一段。暫停鈕旁加靜音鈕，狀態記在 localStorage。
- **why**：沿用公司既有簡報旁白的語音合成做法，不需要 API 金鑰；按下播放才出聲，也符合瀏覽器的自動播放規則。稿子依每個產品的畫面時間寫，太長就精簡文字，不加快語速。
- **順手修**：重新整理時 ResizeObserver 可能在產品還沒建好前就觸發，讀到未定義的相機而報錯，加上防護。
- **替代方案**：(1) 排一張秒數對照表播放——跳段、暫停、分頁切換時容易對不上；(2) 預先把旁白混進影片——首頁是即時 3D，沒有影片可混。

## 20:25 — 首頁退回靜態照片 hero，3D 展示間移到暫存頁

## 20:40 — 預覽頁加上密碼門

- **決策**：`/product-animation/` 與 `/temp/showroom/` 改成要輸入密碼才看得到（front matter `password_gate: true`，兩頁也都加 noindex）。密碼在瀏覽器端比對 SHA-256 雜湊，repo 只存雜湊不存明碼；通過後記在 sessionStorage，同一分頁重新整理不用再輸入。頁面的 3D 程式在解鎖後才動態載入，鎖住時不下載任何模型或音檔。
- **限制**：GitHub Pages 是純靜態主機，沒有伺服器端驗證，這道門只擋一般訪客——3D 模型、音檔仍是公開網址，短數字密碼也能在瀏覽器端被暴力試出。真正需要保密時要改用 Cloudflare Access 之類的前置驗證，或把頁面移出公開 repo。
